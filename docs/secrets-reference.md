# Secrets reference

`make env` generates every local secret in `.env`. You never run these
commands yourself — this page exists so you can see what each value is, and
why it is the length it is, without reading the generator.

**The source of truth is [`infra/scripts/generate-env.sh`](../infra/scripts/generate-env.sh).**
If this page and that script ever disagree, the script is right. Every
`__RAND_HEX_n__` placeholder in it is replaced with a fresh
`openssl rand -hex n`.

There is deliberately no committed `.env.example`. The layout lives in the
generator instead, so no env file is ever committed, and every clone gets
different secrets. This repo is public; a committed env file is the most
common way real credentials end up in one.

---

## What gets generated

| Length | Command | Variables |
|---|---|---|
| **64 hex** (32 bytes) | `openssl rand -hex 32` | `CONSOLE_NEXTAUTH_SECRET`, `LANGFUSE_NEXTAUTH_SECRET`, `LANGFUSE_ENCRYPTION_KEY`, `LANGFUSE_SALT` |
| **32 hex** (16 bytes) | `openssl rand -hex 16` | `POSTGRES_SUPERUSER_PASSWORD`, `PGPASS_KEYCLOAK`, `PGPASS_INFISICAL`, `PGPASS_LITELLM`, `PGPASS_MLFLOW`, `PGPASS_LANGFUSE`, `PGPASS_VERISETTLE_LEDGER`, `PGPASS_VERISETTLE_BACKEND`, `MINIO_ROOT_PASSWORD`, `INFISICAL_ENCRYPTION_KEY`, `INFISICAL_AUTH_SECRET`, `KEYCLOAK_ADMIN_PASSWORD`, `KEYCLOAK_BACKEND_CLIENT_SECRET`, `KEYCLOAK_CONSOLE_CLIENT_SECRET`, `OM_POSTGRES_ROOT_PASSWORD`, `LANGFUSE_CLICKHOUSE_PASSWORD`, `LANGFUSE_REDIS_AUTH` |
| **24 hex** (12 bytes) | `openssl rand -hex 12` | `INFISICAL_ADMIN_PASSWORD`, `AIRFLOW_ADMIN_PASSWORD`, `LANGFUSE_INIT_USER_PASSWORD`, `GRAFANA_ADMIN_PASSWORD` |
| **16 hex** (8 bytes) | `openssl rand -hex 8` | `DEMO_AP_CLERK_PASSWORD`, `DEMO_CONTROLLER_PASSWORD`, `DEMO_CFO_PASSWORD` |

### Prefixed values

A fixed literal prefix glued to random hex, so the value is recognisable in a
log or a dashboard without revealing anything.

| Variable | Generated as |
|---|---|
| `MINIO_ROOT_USER` | `verisettle_admin_` + `openssl rand -hex 4` |
| `LITELLM_MASTER_KEY` | `sk-verisettle-master-` + `openssl rand -hex 16` |
| `LEDGER_API_KEY` | `ldg-` + `openssl rand -hex 16` |
| `VENDOR_LOOKUP_API_KEY` | `vlk-` + `openssl rand -hex 16` |
| `LANGFUSE_INIT_PROJECT_PUBLIC_KEY` | `pk-lf-` + `openssl rand -hex 16` |
| `LANGFUSE_INIT_PROJECT_SECRET_KEY` | `sk-lf-` + `openssl rand -hex 16` |

## Why those lengths

They are not arbitrary, and they are not all the same for a reason.

**32 bytes, because the algorithm requires it.** These are not passwords;
they are fed directly into cryptographic mechanisms with a fixed key size.
Langfuse's encryption key uses AES-256, which needs a full 32-byte key.
NextAuth signs and encrypts session JWTs and its documentation calls for 32
bytes. A shorter value here is not merely weaker — it can be the wrong key
size for the algorithm.

**16 bytes, as a strong generic default.** The `PGPASS_*` values, MinIO's
root password, the Keycloak client secrets and the rest are strong random
secrets rather than keys tied to an algorithm. 16 bytes is 128 bits of
entropy from a cryptographically secure generator, which is far beyond
brute-forcing.

**12 and 8 bytes, because a human has to type them.** The admin logins and
the three demo accounts get read off the screen and typed into a login form
during setup or a demo. 12 bytes is 96 bits, 8 bytes is 64 bits — still
randomly generated by `openssl`, never a guessable human-chosen password, but
short enough to retype without misery. These protect local development
accounts on your own machine, nothing else.

## What is *not* generated

### Real provider keys — you supply these

Obtained from each provider's dashboard. `make env` leaves them blank.

```
OPENAI_API_KEY
GROQ_API_KEY
```

### Server-generated — filled in during setup

Each of these is created by Infisical, SPIRE, Keycloak or LiteLLM when its
setup script runs, and printed for you to paste into `.env`.

```
INFISICAL_ORG_ID
INFISICAL_PROJECT_ID
SPIRE_AGENT_JOIN_TOKEN
PAYMENT_EXECUTION_CLIENT_ID
PAYMENT_EXECUTION_CLIENT_SECRET
LITELLM_KEY_AGENT_EXTRACTION
LITELLM_KEY_AGENT_RISK_SCORING
LITELLM_KEY_AGENT_APPROVAL
LITELLM_KEY_AGENT_PAYMENT_EXECUTION
LITELLM_EXTRACTION_KEY
```

> **`LITELLM_EXTRACTION_KEY` is the exception.** It is labelled auto-filled,
> but `provision-litellm-keys.py` does not write it. Set it by hand to the
> same value as `LITELLM_KEY_AGENT_EXTRACTION`. Left empty, the DeepEval gate
> falls back to `LITELLM_MASTER_KEY` and runs unscoped and unbudgeted.

### Plain configuration — not secrets at all

```
KEYCLOAK_ADMIN
INFISICAL_ADMIN_EMAIL
INFISICAL_ADMIN_ORGANIZATION
SPIRE_TRUST_DOMAIN
USASPENDING_AGENCY
USASPENDING_FISCAL_YEAR
COMPOSE_PROJECT_NAME
```

`USASPENDING_AGENCY` contains spaces and **must stay quoted** in `.env`.
Unquoted, every script that runs `. ./.env` dies with `./.env: of: not found`,
which is a confusing way to learn about shell word-splitting. The generator
quotes it; if you edit it by hand, keep the quotes.

## Handling

`.env` is written mode 0600 and is gitignored, along with the rendered
Keycloak realm and the Infisical identity files. Nothing here should ever be
committed, and nothing here is a real credential for anything outside your own
machine — except the two provider API keys, which are yours and are real.

If you need to start over, `make clean` destroys the volumes those secrets are
baked into, and `FORCE=1 make env` will then write a fresh `.env`.
